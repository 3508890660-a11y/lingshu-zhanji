# 灵枢战纪 · 12 模型颜色构筑脚本

12 个真实模型各自读规则与卡表、自选颜色、构筑 30 张卡组，并写成游戏可直接加载的 `build(pool)` / `choose(view, moves)` 脚本。主代理只提供接口、卡表、自检工具与循环赛，不指定颜色或打法。

## 目录

```
agents/
  agents.json              # 12 个模型的目录：显示名、真实 model ID、颜色、策略、脚本/说明路径
  agent-<id>.js            # 12 份脚本（游戏“脚本编辑器”的源码格式，无 import/export）
  design/<id>.md           # 12 份公开设计说明（颜色、卡组、曲线、优先级、取舍）
  progress/<id>.json       # 子代理进度上报
  results.json / .md       # 4 轮循环赛（528 局）完整结果与会话账目

tools/
  agent-color-brief.md     # 本轮统一任务说明
  agent-selftest.mjs       # 单脚本自检：编译 → 组卡 → 校验 → 20 局
  agents-run.mjs           # 12 脚本循环赛：每对每轮各先手一次，输出 results.*
  report-progress.mjs      # 子代理进度上报
```

## 在游戏里使用

1. `node server.mjs` 启动，浏览器打开 `http://127.0.0.1:5173/`；
2. 进入「脚本」页，点 **载入模型脚本**；
3. 左右两侧的 AI 下拉框会出现 12 个「（模型）」脚本，选择后点「按脚本重建」或直接开局。

脚本只在本页内存中，刷新后重新点一次即可；不会写入 `localStorage`，也不会覆盖你保存的自定义脚本。

## 命令行

```bash
# 单脚本自检（编译 + 组卡 + 校验 + 20 局 vs CONTROL）
node tools/agent-selftest.mjs agents/agent-hy4.js 青 20

# 12 脚本循环赛（每对每轮各先手一次，4 轮 = 528 局）
node tools/agents-run.mjs --seeds 4 --out agents/results
```

## 关于颜色分布（必须说明）

本轮 12 个模型里 **11 个自选青、1 个自选银**。原因不是脚本写错，而是 `README.md` §9/§10 的平衡实测把青标成强势色（69%），多个模型直接引用了这张表；银则是 §9 的 96% 预组数据。也就是说，这一轮实际是：

- **同色（青）构筑 + 脚本质量对照**：11 份青脚本的卡组并不相同（10–12 名目、曲线 1–2 费 15–21 张），排名反映的是同色内的构筑与决策差异；
- **跨色对照只有一个样本**：deepseek v4pro 的银翼方阵拿到第 3（65.91%），说明银在同台竞技下并不弱。补充的 50 局正面对照：KIMI 2.8preview（青）29-21（58%）胜 deepseek v4pro（银），青冠对银仍有优势但不碾压。

如果要做真正的“跨色”对照，需要再开一轮：**禁止读 §9/§10 的赛果**，或直接把 11 色分配给 12 个模型。本目录保留当前这一轮的原样结果，不替模型改颜色。
