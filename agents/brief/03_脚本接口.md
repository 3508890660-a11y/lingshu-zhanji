# 03 · AI 脚本接口（硬契约）

> 本文件只写接口契约。

## 1 编译方式

脚本是**一段 JS 源码**，不是 ES 模块。引擎用 `new Function('api', src + '; return {build, choose, meta}')` 编译。

- 不得出现 `import` / `export` / `require`。
- `api` 注入：`CARDS`、`scoreCard`、`autoBuild`、`byId`、`costOf`。
- 必须声明 `meta`、`build`、`choose`；`block` 可选。

```js
const meta = {
  name: '显示名 · 你的策略名',   // 必须包含本行「显示名」（测试做大小写不敏感匹配）
  desc: '执行模型 <模型ID>；颜色 <色>；策略 <策略名>；<一句话理由>',
  id: 'model:<短 id>',
  color: '<主色>'
};

function build(pool) { /* 返回合规卡组 */ }

function choose(view, moves) {
  return moves[moves.length - 1]; // 兜底：pass
}

function block(view, bmoves) {   // 可选
  return bmoves[bmoves.length - 1];
}
```

## 2 `build(pool)`

`pool` 是**已按主色 + 灰过滤**的原始卡对象数组，字段：

```ts
{ id, name, type, cost:{k,n}, atk, imp, hp, kw:[], effects:[], rare, text, sr, av }
```

- `type`：`单位` / `法术` / `装备` / `地标` / `结界` / `金币卡`。
- `cost.k` 是资源种类，`cost.n` 是数值。
- **没有预计算 `score` 字段**；要用评分自己写，或用 `api.scoreCard(c)` / `api.autoBuild(pool)`。
- 返回值两种都行：`[{ id:'LQ01-037', n:3 }, ...]` 或文本 `'3x LQ01-037'`。
- 返回 `null` / 抛异常 → 引擎回退 `autoBuild`；**本轮要求自己返回合规卡组，不依赖回退**。
- 卡组必须过 `validateDeck`（见 `01_基本规则.md` §4）。

## 3 `choose(view, moves)` 与 `block(view, bmoves)`

### `view` 字段

```ts
{
  turn, round, active,
  me: {
    color, life, res, resName,
    avatar: { name, desc, used, timing, atk, imp, lv },  // timing: 'early' | 'late'；atk/imp/lv 供粉色判断能否作战
    hand: [{ id, name, type, cost, atk, imp, hp, kw, effects, text, sr, av }],
    board: [{ uid, name, atk, imp, hp, maxHp, kw, frozen, attacked, equips }],
    lands: string[], deck: number, grave: number, plays: number,
    av: number | undefined,                      // 金：行动值
    forge: number, outerReady: number, exile: number,
    // 粉色专属（其余颜色为 undefined / 空数组）
    evolution: [{ lv, name }],                   // 解放区待骑升的 Lv1~Lv4
    souls: [{ name, state }],                    // 魂装源：state = 'active' | 'sleep'
    soulGrave: number,                           // 已移出的魂装源张数
    rideUsed: number, avatarAtkUsed: number,     // 本回合已骑升 / 已用灵体攻击次数
    ap: number | undefined, apMax: number | undefined
  },
  opp: { color, life, res, resName, handCount, board, lands, deck, grave },
  market: [{ id, name, type, cost, atk, imp, hp, kw, av }],  // 公共市场（金）
  over
}
```

- `me.hand` 是**完整卡面**；`opp.handCount` 只有数量——**对手手牌不可见**。
- `me.board` 的 `atk/imp` 是**当前值**（已含 buff），`hp/maxHp` 是当前／上限。
- `me.res` 是本回合可用资源数（门槛色是门槛值，不随打牌减少）。

### `moves` 类型（引擎已过滤非法动作）

| 类型 | 字段 | 说明 |
|---|---|---|
| `play` | `{ i, target?, mode? }` | `i` 是手牌下标；`target` 是需要指定目标的卡的单位 uid；`mode:'forge'` 是橙色装备横置进锻造区 |
| `avatar` | `{}` | 启动灵体能力，每回合 1 次 |
| `buy` | `{ i }` | 金：购买市场区第 `i` 张 |
| `ascend` | `{ id }` | 升灵仪式：降临外枢灵体 |
| `ride` | `{}` | 粉：骑升到下一阶（每回合 1 次，需解放区有该阶且已到阶梯回合） |
| `attire` | `{ uid }` 或 `{ hand: i }` | 粉：魂装，把场上单位或 1 张手牌叠到灵体下（1 AP） |
| `awaken` | `{}` | 粉：魂装觉醒，活跃源翻沉睡，灵体本回合 +2 ATK（1 AP） |
| `resonate` | `{}` | 粉：魂装共鸣，沉睡源翻活跃并抽 1（1 AP） |
| `attack` | `{ uid, target }` 或 `{ avatar: true, target }` | `target` 是敌方单位 uid 或 `'face'`；`avatar: true` 是粉色灵体亲自作战（1 AP，Lv2 起，Lv4 蕾每回合 2 次） |
| `pass` | `{}` | 结束回合 |

`bmoves` 只有 `{type:'block', uid}` 与 `{type:'noBlock'}`。

## 4 硬约束（违反即判不合格）

1. `choose` 必须返回 **`moves` 数组里的某一个对象引用**；`block` 同理返回 `bmoves` 里的对象。不得新建 `{type:'pass'}`。
2. 不得修改 `view` / `moves` / `bmoves`；不得对原数组 `sort()`（要排序先 `slice()`）。
3. 零依赖：不得出现 `import` / `require`；不得访问 `window`、`fs`、网络。
4. 不得死循环、不得抛异常、单次决策不超过 3000ms。
5. 未知 `moves` 类型要安全兜底到 `pass`（或最后一个合法动作）。
6. 不得硬编码卡牌实例 `uid`；卡号／卡名可以硬编码，但必须对未知卡与效果兜底。
7. `choose` 抛异常或返回非法动作时，引擎记录一条异常并把该步按 `pass` 处理——自检会把它计为 `errors`，**必须做到 0**。

## 5 一个最小可用骨架

```js
function choose(view, moves) {
  const plays = moves.filter(m => m.type === 'play');
  if (plays.length) return plays[0];
  const face = moves.filter(m => m.type === 'attack' && m.target === 'face');
  if (face.length) return face[0];
  return moves[moves.length - 1];
}
```

## 3.5 `respond(view, ctx, moves)`（可选）

响应窗口在**你不是行动方**时打开，三个时点：

| `ctx.kind` | 时点 | `ctx` 额外字段 |
|---|---|---|
| `play` | 对手刚宣告一张卡、尚未结算 | `card`：该卡卡面（含 `type`／`text`／`cost`） |
| `attack` | 对手宣告攻击、伤害尚未结算 | `attacker`：`{ name, atk, imp, hp }`；`target`：`'face'` 或单位名 |
| `endTurn` | 对手宣告结束回合、结束效果尚未结算 | — |

`moves` 里只有两种动作：

- `{ type:'respond', i, target? }`：打出自己第 `i` 张手牌里的**瞬间卡**（`target` 只在卡面需要目标时出现）；
- `{ type:'pass' }`：不响应。

规则：

1. **没写 `respond` 的脚本一律视为 pass**，不影响旧脚本；`respond` 抛异常也按 pass 处理。
2. `kind:'play'` 时打出「反击」类瞬间卡 → 对手那张卡**整体无效并置入弃牌区**（已支付的费用不退）。
3. 其他情况按该瞬间卡的实际效果结算（例如 `LQ01-041` 对攻击者造成 3 点伤害）。
4. 每个时点只开一次窗口，不实现多轮交替响应链。
